# W9 handoff — Copilot

Implemented the global Operations Copilot as an accessible, responsive dialog using the existing UI kit and Cloudflare-style neutral/orange tokens. Six suggested questions work without a network. Answers provide scope-filtered source record drawers and workspace links. Conversations clear on role change and demo reset. Refusals record `copilot.refused` in local activity history; storage failures are visible and never result in controlled actions.

## Evidence and boundaries

- Every calculation and source lookup starts with `scopeCopilotData`. Out-of-scope explicit site/asset requests return no records. Partial-site roles cannot receive the six-site rollout benefit.
- A010 is first by total historical lost margin, third by historical parts-wait dollars. Its answer explicitly distinguishes the queue's optional continuous-stop/sample-lead-time comparison from historical ranking and forecasts.
- Bearing-kit stock/specification is labeled sample and has its own current-demo source row. The historical spare-fill percentage is never treated as a parts quantity.
- Mesa blockers read current HSE verification overlays. Historical imported status remains available in the source drawer. Pilot release and actual field authorization remain distinct.
- $721,000 staggered year one and $842,000 full year are named gross modeled estimates, with their rollout schedule and the O4 workbook assumption clearly separated. The source chip says the named rollout is Product Guide D1; the workbook row supports O4's 60% assumption, not a claim that the named preset is a measured result.
- Achieved savings, actual live sensor conditions and supplier promises are unavailable. Generic questions fall back plainly without fabricated data.

## Optional live integration

Live model access is intentionally unavailable. The public demo's browser-selected roles are not server authentication. A configured API key alone must not expose a paid proxy or let the browser submit arbitrary role/context. `/api/copilot` validates method, JSON, size and question length, then returns an explicit offline 503 without any external fetch or credential exposure, even if a secret is present. An authenticated server identity with server-owned role/site mapping is required before optional model streaming can be enabled. No API key, SDK, runtime dependency, Vite secret, or model name was added. Existing `/api/sync-excel` behavior is preserved.
