# W1 handoff

## Done
- HSE site pilot gate uses original open severity-5 source actions with a separate persistent verification overlay. Imported Closed rows cannot be changed.
- Supervisor-only, site-scoped writes check the authenticated session actor, not caller-supplied role claims.
- Required note plus one to three validated photo/document uploads, maximum 2 MB each. Storage errors surface in the form.
- Verification does not release a gate. Explicit typed-name release produces Ready; a subsequent receipt produces Live once. Earlier receipts cannot replay into Live after release. Relock and undo verification require a reason.
- Six site cards, sourced action drawers with real record IDs, overdue/cost/person-hour details, verification stamps, non-blocking action groups and read-only permission notes.
- Summary widget and fixed pilot-versus-field-work safety context.

## How to see it
- Open #/hse. HSE supervisor Sam Patel can verify Mesa, Arroyo and Prairie actions. Other roles see read-only details.
- Verify both Arroyo severity-5 actions with note and PNG/JPEG/WebP/PDF/text evidence, then release by typing Sam Patel.
- Receive a new Arroyo parts request to trigger Live. Re-lock returns the site to Locked until another explicit release.

## Known gaps
- Prototype localStorage identity and evidence storage are not production authentication or an HSE system.
- Browser QA/screenshots deferred to orchestrator as agreed.
- Multi-store activity/state writes are not atomic; a storage failure after a successful gate write may leave its activity entry unsaved.
